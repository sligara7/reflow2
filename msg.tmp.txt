THE SURPLUS HALF OF DETECT. Every existing gap asks what is MISSING — nothing
satisfies this, nothing builds it, nothing verifies it. Checked all seven
capability gaps: NOT ONE asks whether anything is DOWNSTREAM of a built thing.
unmotivated_capability is the near miss and it is about INTENT — a capability
can satisfy its requirement perfectly and still be consumed by nothing, which
is the expensive case, because the paperwork is complete and the code is dead.

Computable today: realized/verified, no incoming DEPENDS_ON, no PART_OF_FLOW,
no Actor INTERACTS_WITH.

THE BOUND SHIPS WITH IT: the graph sees DESIGN-level demand and nothing about
runtime usage, so the finding is "nothing in this design consumes X", never
"X is unused". A feature real users call daily whose consumer was never modelled
has the identical graph shape. Said in the requirement and in the capability,
because a detector that skipped it would confidently recommend deleting working
code — the unmet_needs: 0 failure again.

Runtime usage is deliberately NOT here: dec:bl-155 and
dec:idea-measure-the-surface already hold that question and it needs telemetry.


AND dec:idea-is-session-context-already-in-the-graph — Anthony asked whether
capturing session context is moot, since every decision an agent makes already
lands in the graph.

cap:session-memory (PLANNED since 2026-07-25, his own framing) already answers
it, and more sharply than yes or no: "Decision.rationale and ChangeEvent already
capture fragments of the why; what lives only in the session is the CONNECTIVE
TISSUE — what was tried, what was rejected and on what grounds, which findings
turned up while doing something else."

THIS SESSION IS THE EVIDENCE, self-implicating rather than hypothetical. Its
design content is all in the graph. Its process knowledge is in NONE of it —
hashing before the last edit five times, piping a gate into tail and pushing
past red, merging a stack into already-squashed base branches — and every bit of
that lives in a markdown memory file OUTSIDE reflow2, which is the kind of file
dec:what-lives-where exists to retire.

AND THE PART THAT BEARS ON THE BLOB: the store was never the mechanism for this,
and cap:session-memory says so already — "a pointer to a 3 MB transcript is a
RECEIPT, not documentation: leaning on it recreates the markdown problem one
level down." Its actual design needs no store: takeaways as first-class graph
content anchored to the session's epoch, with the transcript a Fragment carrying
the session UUID — a pointer, not bytes.

So the session-context justification for the content store does not survive, and
not because session context is worthless: because its value is in distilled
nodes, which need no store. That removes a founding motivation from
dec:idea-discontinue-the-content-store rather than complicating it.
